2 Geographic vs. projected CRSs

Geographic CRS: positions are angles

Latitude φ: angle north or south of the equator, measured at Earth's center (side view)
Longitude λ: angle east or west of Greenwich (view from above the North Pole)
  • Units: degrees (angles, not distances)
  • Longitude −180° to 180°; latitude −90° to 90°
  • Examples: WGS 84 (EPSG:4326), NAD83 (EPSG:4269)

Projected CRS: positions are distances on a flat grid

  • Flattens one part of the globe onto a plane (a projection)
  • Units: meters (sometimes feet), measured from the grid’s origin
  • Built on top of a geographic CRS
  • Examples: EPSG:2169 (Luxembourg), EPSG:5070 (NLCD), UTM zones

A degree is not a fixed distance

  • 1° of latitude ≈ 111 km everywhere
  • 1° of longitude shrinks toward the poles, because the meridians converge

3 Datums and ellipsoids

  • Ellipsoid: a smooth mathematical shape (size + flattening)
  • Datum: an ellipsoid + where it’s pinned to the real Earth
  • Change the datum and the same lat/lon points to a different spot

datumGeom = {
  const W = 640, H = 380;
  const earth = {x: 430, y: 195};             // Earth's center of mass
  // The lumpy "real" Earth (a geoid, hugely exaggerated): a wobbly radius
  const rEarth = th => 118 * (1 + 0.05 * Math.sin(3 * th + 0.5) + 0.035 * Math.cos(5 * th) + 0.02 * Math.sin(8 * th + 1));
  const earthPath = d3.line().curve(d3.curveCardinalClosed)(
    d3.range(0, 2 * Math.PI, Math.PI / 60).map(th => [earth.x + rEarth(th) * Math.cos(th), earth.y - 0.9 * rEarth(th) * Math.sin(th)])
  );
  // Meades Ranch, Kansas: a point on the upper left of the cross-section
  const thPin = 125 * Math.PI / 180;
  const pin = [earth.x + rEarth(thPin) * Math.cos(thPin), earth.y - 0.9 * rEarth(thPin) * Math.sin(thPin)];
  // Clarke 1866 (NAD27): placed so its surface passes through the pin
  const nad27 = {rx: 100, ry: 82};
  nad27.x = pin[0] - nad27.rx * Math.cos(thPin);
  nad27.y = pin[1] + nad27.ry * Math.sin(thPin);
  // WGS 84: centered on Earth's center of mass, a best fit everywhere
  const wgs84 = {rx: 121, ry: 104, x: earth.x, y: earth.y};
  const start = {rx: 112, ry: 94, x: 140, y: 195};  // ellipsoid parked on the left
  return {W, H, earth, earthPath, pin, nad27, wgs84, start};
}

How much does it matter?

Same coordinates for the AU campus, labeled NAD27 vs. NAD83:

Show code 
# One pair of numbers: longitude, latitude
au_xy <- st_point(c(-77.0887, 38.9365))

# The same numbers, labeled with two different datums
au_nad27 <- st_sfc(au_xy, crs = 4267)
au_nad83 <- st_sfc(au_xy, crs = 4269)

# Convert the NAD27 point to NAD83, so both are on one datum
au_nad27_converted <- st_transform(au_nad27, 4269)

# How far apart are "the same" coordinates on the ground?
st_distance(au_nad83, au_nad27_converted)
Units: [m]
         [,1]
[1,] 28.71194
  • NAD27 vs. NAD83: ≈ 28 m, enough to cross a street or a tract boundary
  • NAD83 vs. WGS 84: ≈ 1–2 m in the US, rarely matters for tracts or 30 m rasters
  • R treats any CRS difference as a mismatch, so TRI points (WGS 84) must still be transformed to join Census tracts (NAD83)
NoteBehind the scenes: datum shifts need extra files
  • Accurate NAD27 → NAD83 conversion uses a grid of measured shifts, downloaded separately
  • If PROJ (the library under sf and terra) can’t find it, it falls back to a “ballpark” conversion, which can mean zero shift, no error
  • This page was built with sf_proj_network(TRUE), which lets PROJ fetch grids as needed
  • The general lesson: running without an error isn’t proof it did what you think

4 Projections: flattening is a trade

Families: what you project onto

Show code 
{
  // Three schematic diagrams (sphere + surface, with projection rays),
  // each above the real graticule that family produces.
  const pw = 220, ph = 340;
  const cx = 110, cy = 110, r = 55;

  function base(svg) {
    svg.append("circle").attr("cx", cx).attr("cy", cy).attr("r", r).attr("fill", col.ocean).attr("stroke", col.ink).attr("stroke-width", 1.5);
    svg.append("ellipse").attr("cx", cx).attr("cy", cy).attr("rx", r).attr("ry", 10).attr("fill", "none").attr("stroke", col.grid);
    svg.append("circle").attr("cx", cx).attr("cy", cy).attr("r", 2.5).attr("fill", col.ink);
  }
  // A ray from the sphere's center, through the sphere, to the surface
  function ray(svg, x2, y2) {
    const a = Math.atan2(y2 - cy, x2 - cx);
    svg.append("line").attr("x1", cx).attr("y1", cy).attr("x2", x2).attr("y2", y2).attr("stroke", col.orange).attr("stroke-width", 1.3);
    svg.append("circle").attr("cx", cx + r * Math.cos(a)).attr("cy", cy + r * Math.sin(a)).attr("r", 3).attr("fill", col.orange);
    svg.append("circle").attr("cx", x2).attr("cy", y2).attr("r", 3.5).attr("fill", col.red);
  }
  // The graticule this family produces, drawn in the lower part of the panel
  function grat(svg, projection) {
    const box = [[20, 215], [pw - 20, ph - 30]];
    projection.fitExtent(box, {type: "Sphere"});
    const path = d3.geoPath(projection);
    svg.append("path").attr("d", path({type: "Sphere"})).attr("fill", col.ocean).attr("stroke", col.ink);
    svg.append("path").attr("d", path(land)).attr("fill", col.land);
    svg.append("path").attr("d", path(d3.geoGraticule().step([30, 30])())).attr("fill", "none").attr("stroke", col.grid);
  }
  function panel(title, note, draw, projection) {
    const svg = d3.create("svg").attr("viewBox", [0, 0, pw, ph]).style("width", "100%").style("max-width", "260px");
    draw(svg);
    grat(svg, projection);
    svg.append("text").attr("x", pw / 2).attr("y", ph - 8).attr("text-anchor", "middle").attr("font-size", 12).attr("fill", col.ink).text(note);
    return html`<div style="text-align:center"><div style="font-weight:600">${title}</div>${svg.node()}</div>`;
  }

  const cylinder = panel("Cylindrical", "touches along the equator", svg => {
    svg.append("line").attr("x1", cx - r).attr("y1", 20).attr("x2", cx - r).attr("y2", 200).attr("stroke", col.blue).attr("stroke-width", 2);
    svg.append("line").attr("x1", cx + r).attr("y1", 20).attr("x2", cx + r).attr("y2", 200).attr("stroke", col.blue).attr("stroke-width", 2);
    svg.append("ellipse").attr("cx", cx).attr("cy", 20).attr("rx", r).attr("ry", 9).attr("fill", "none").attr("stroke", col.blue).attr("stroke-width", 2);
    svg.append("ellipse").attr("cx", cx).attr("cy", 200).attr("rx", r).attr("ry", 9).attr("fill", "none").attr("stroke", col.blue).attr("stroke-width", 2);
    base(svg);
    svg.append("ellipse").attr("cx", cx).attr("cy", cy).attr("rx", r).attr("ry", 10).attr("fill", "none").attr("stroke", col.red).attr("stroke-width", 2);
    ray(svg, cx + r, cy - r * Math.tan(30 * Math.PI / 180));
    ray(svg, cx + r, cy - r * Math.tan(50 * Math.PI / 180));
    ray(svg, cx - r, cy + r * Math.tan(35 * Math.PI / 180));
  }, d3.geoEquirectangular());

  const cone = panel("Conic", "touches along one parallel", svg => {
    // Cone tangent to the sphere at 35° N; apex on the axis above the pole
    const phi = 35 * Math.PI / 180;
    const tx = cx + r * Math.cos(phi), ty = cy - r * Math.sin(phi);
    const apexY = ty - (tx - cx) / Math.tan(phi);
    const baseY = 165, baseX = tx + (baseY - ty) * Math.tan(phi);
    base(svg);
    svg.append("path").attr("d", `M${2 * cx - baseX},${baseY} L${cx},${apexY} L${baseX},${baseY}`).attr("fill", "none").attr("stroke", col.blue).attr("stroke-width", 2);
    svg.append("ellipse").attr("cx", cx).attr("cy", baseY).attr("rx", baseX - cx).attr("ry", 11).attr("fill", "none").attr("stroke", col.blue).attr("stroke-width", 2);
    svg.append("ellipse").attr("cx", cx).attr("cy", ty).attr("rx", tx - cx).attr("ry", 7).attr("fill", "none").attr("stroke", col.red).attr("stroke-width", 2);
    // Rays hit the cone's side: intersect each ray with the cone line
    for (const deg of [15, 55]) {
      const a = -deg * Math.PI / 180;
      const dx = Math.cos(a), dy = Math.sin(a);
      // Cone side: from apex (cx, apexY) toward (baseX, baseY)
      const ux = baseX - cx, uy = baseY - apexY;
      const den = dx * uy - dy * ux;
      const s = ((cx - cx) * uy - (apexY - cy) * ux) / den;
      ray(svg, cx + s * dx, cy + s * dy);
    }
  }, d3.geoConicEqualArea().parallels([30, 50]));

  const plane = panel("Azimuthal (planar)", "touches at one point", svg => {
    base(svg);
    const py = cy - r;
    svg.append("path").attr("d", `M${cx - 85},${py + 10} L${cx - 45},${py - 10} L${cx + 85},${py - 10} L${cx + 45},${py + 10} Z`)
      .attr("fill", col.blue).attr("fill-opacity", 0.08).attr("stroke", col.blue).attr("stroke-width", 2);
    svg.append("circle").attr("cx", cx).attr("cy", py).attr("r", 4).attr("fill", col.red);
    for (const deg of [60, 115]) {
      const a = deg * Math.PI / 180;
      ray(svg, cx + (cy - py) / Math.tan(a), py);
    }
  }, d3.geoAzimuthalEquidistant().rotate([0, -90]));

  return html`<div class="widget" style="display:grid;grid-template-columns:repeat(auto-fit,minmax(200px,1fr));gap:1rem">${cylinder}${cone}${plane}</div>`;
}
  • Red = where the surface touches the globe: least distortion there
  • Distortion grows with distance from the red line or point
  • Conic suits mid-latitude areas wider than tall: the US, Maryland

Properties: what a projection preserves

First choice: pick one (no map can do both)

  • Equal-area: areas correct, shapes stretched
  • Conformal: local shapes and angles correct, areas stretched
  • Or a compromise: neither exactly, both errors kept moderate (good for world maps to look at)

Extras: true only from one point or along certain lines

  • Equidistant: distances from the center point are correct
  • Azimuthal: directions from the center point are correct (all planar projections have this, hence the family name)
  • Extras combine with the first choice: e.g. Lambert azimuthal equal-area

routeFacts = {
  const R = 6371, rad = Math.PI / 180;
  const [l1, p1] = dc.map(v => v * rad), [l2, p2] = london.map(v => v * rad);
  // Compass bearing from a to b at the start of a great circle
  const bearing = (la1, ph1, la2, ph2) => {
    const y = Math.sin(la2 - la1) * Math.cos(ph2);
    const x = Math.cos(ph1) * Math.sin(ph2) - Math.sin(ph1) * Math.cos(ph2) * Math.cos(la2 - la1);
    return (Math.atan2(y, x) / rad + 360) % 360;
  };
  const gcStart = bearing(l1, p1, l2, p2);
  const gcEnd = (bearing(l2, p2, l1, p1) + 180) % 360;
  const gcKm = d3.geoDistance(dc, london) * R;
  // Rhumb line: one bearing the whole way
  const dPsi = Math.log(Math.tan(Math.PI / 4 + p2 / 2) / Math.tan(Math.PI / 4 + p1 / 2));
  const rhumbBearing = (Math.atan2(l2 - l1, dPsi) / rad + 360) % 360;
  const rhumbKm = Math.abs((p2 - p1) / Math.cos(rhumbBearing * rad)) * R;
  return {gcStart, gcEnd, gcKm, rhumbBearing, rhumbKm};
}

function moveTo(feature, newLat) {
  const [lon0, lat0] = d3.geoCentroid(feature);
  const toOrigin = d3.geoRotation([-lon0, -lat0]);   // centroid -> (0, 0)
  const toTarget = d3.geoRotation([-lon0, -newLat]); // (lon0, newLat) -> (0, 0)
  const move = pt => toTarget.invert(toOrigin(pt));
  const walk = c => typeof c[0] === "number" ? move(c) : c.map(walk);
  return {type: "Feature", geometry: {
    type: feature.geometry.type, coordinates: walk(feature.geometry.coordinates)
  }};
}

8 Check yourself

Note1. A bounding box reads xmin: 316268 ymin: 4295630 xmax: 334407 ymax: 4318264. Degrees or meters? Projected or geographic?
  • Meters, so projected: longitudes stop at ±180, latitudes at ±90
  • Hundreds of thousands and millions look like UTM (this is Washington, DC, in UTM zone 18N)
Note2. extract(r, polygons, fun = mean) gives you some NaNs. Name three possible causes, and how you’d tell them apart.
  • All NaN: the layers don’t overlap. Usually a CRS mismatch (today’s failure); sometimes the raster covers a different area. Compare st_bbox() and ext()
  • Some NaN, with na.rm = TRUE: those polygons fall only on no-data cells or outside the raster’s edge. Plot the polygons on the raster and look at where the NaN ones are
  • Many NaN, without na.rm = TRUE: any polygon that touches even one no-data cell returns NaN. Here, 9 of 12 cantons did. Add na.rm = TRUE, and decide whether a partial average is acceptable
Note3. An AI suggests st_transform(tri, 2263) before buffering TRI facilities in Baltimore by 1,000. Look up EPSG:2263. What’s wrong?
  • It’s NAD83 / New York Long Island (ftUS): the wrong place, and the units are US feet
  • A buffer of 1,000 would be 1,000 ft (about 305 m), not 1 km
  • Baltimore is outside its area of use, so distortion is larger too
  • Better: 26985 (Maryland, meters) or 26918 / 32618 (UTM 18N)
Note4. TRI facilities are in EPSG:4326 and tracts in EPSG:4269, about a meter apart. What happens if you st_join() them without transforming? Loud or silent?
  • Loud: st_join() stops with st_crs(x) == st_crs(y) is not TRUE
  • sf requires identical CRSs and can’t judge whether a meter matters for your question
  • Fix: transform one to match the other (or both to a projected CRS you’ll measure in)
